NOTE ON THE "FOUR DIFFERENT CTA LABELS" FINDING
--------------------------------------------------------------------------------
When I went to fix this, I found the four buttons don't actually all go to
the same place — I was wrong to say they did in the original review:

  - Home hero "Recent Works"   -> scrolls to the Featured Projects section
                                   further down the SAME Home page (never
                                   navigates to /projects at all)
  - Projects hero "Explore
    Projects"                  -> scrolls down within the /projects page
                                   to the full list below
  - About CTA "View My
    Projects"                  -> navigates to the /projects route
  - Nav dropdown "All Projects" -> navigates to the /projects route

Renaming all four to identical text would have made Home's button actively
misleading (it would say "View Projects" but not go to the Projects page).
So I only merged the two that are genuinely the same action:
About's CTA now matches the nav dropdown's wording ("View All Projects").
Home's hero button and the Projects-page scroll button were left as-is
because their destinations really are different — this is really the
homepage-duplication issue surfacing again, not an isolated copy problem.


1. TYPOGRAPHY
--------------------------------------------------------------------------------
No custom typeface anywhere in the codebase — every page runs on the bare
system-ui stack. That's a legitimate choice, but it's then asked to perform
two unrelated personalities:

  About.jsx / AboutHero.jsx heading style:
    "Aref Saboor" — font-weight 300, tight tracking — quiet, editorial.

  HomepageContent.jsx heading style:
    "Featured Projects" — font-weight 900, tight tracking — loud, bold,
    SaaS-landing-page voice.

  Same typeface family, opposite temperament. A visitor's eye has to
  recalibrate what kind of site this is every time they cross from Home's
  lower sections into About or Projects.

[KEEP] The bold/thin name lockup is a real signature.
  "Aref" (bold) + "Saboor" (thin) repeats identically in the navbar, hero,
  footer, and mobile sidebar. That's exactly the kind of small, consistent
  mark a portfolio should have. Don't change it.

[NOT DONE] No typographic point of view.
  Relying entirely on the system font means every visual "voice" comes from
  weight and tracking alone. Right now the type says nothing about design
  taste, only about restraint. Suggestion: one characterful display face
  for names/headlines, system stack kept for body copy and UI chrome. Not
  implemented — picking a specific typeface is a taste decision for you to
  make, not something to impose unilaterally.

[NOT DONE] Italic is the only emphasis device, used identically on three
  different pages: "Interface Craftsman" (About), "Let's Work Together"
  (Contact), "Beyond the Code" (About again). Minor and subjective — left
  alone unless you want it varied.

4. VISUAL CRAFT
--------------------------------------------------------------------------------
[KEEP] The hero's "lower-third" caption boxes — genuine idea, left alone.

[DONE] Mobile menu dead zone.
  Before: 360px empty gap (43% of a 390x844 screen), measured via
  bounding-box coordinates between the nav links and the bio/social block.
  Fix: changed the sidebar's flex container from justify-between to
  justify-center with an explicit gap-16 (sm:gap-20).
  After: re-measured at 77px — the visual gap now reads as intentional
  breathing room, not a layout gap.

[DONE] Button hierarchy in the Projects hero carousel (src/sections/
  ProjectsHero.jsx). "Visit Live" and "Live Vercel" were rendering with the
  exact same solid-teal style. Now only the first link in each project's
  link list renders solid/primary; any additional links render as
  outlined/secondary. Checked LinkButtons.jsx (used on the full Projects
  list page) separately — that one already had correct primary/secondary
  styling, so nothing needed fixing there.

[DONE] Credential icons undersold real credentials.
  Before: bare 32px (w-8 h-8) monochrome icon, no background.
  After: 48px container (w-12 h-12) with a rounded teal-50 background chip
  around a 28px (w-7 h-7) icon — confirmed visually larger and more present
  in a live screenshot.

[NOT DONE] Three icon families (line/filled/flat brand marks) in one site.
  Needs a decision on which single icon system to standardize toward —
  bigger-scope change than the others, left as a recommendation.

[NOT DONE] Logo click on Home triggers a full page reload
  (window.location.reload() in Navbar.jsx) to replay the greeting-loader
  animation. Not fixed because removing the reload would also remove the
  "replay intro on click" behavior entirely — that's a product decision
  (do you want this feature at all, and if so, should it be rebuilt without
  a reload via lifted state in App.jsx?), not a mechanical bug fix.
